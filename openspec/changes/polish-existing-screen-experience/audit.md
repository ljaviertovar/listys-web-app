# Auditoría de UI/UX existente — mobile first

Fecha: 2026-10-18. Entrega de propuesta; ningún hallazgo se ha corregido todavía.

## Evidencia y límites

- **B**: observado con Playwright CLI en Chromium en la sesión autorizada. Pantallas autenticadas en `https://listys-web-app.vercel.app`; públicas/auth en el servidor del usuario, accesible desde WSL a través del host Windows en el puerto 3000.
- **C**: verificado leyendo el código local; no equivale a reproducción funcional en ese build.
- **V**: validación pendiente, explícitamente exigida para aceptar la implementación.
- Viewports: dashboard 320/390/430/768/1280 px; recorridos autenticados principalmente 390×844; merge y subida también 320×568; públicas/auth tienen comprobaciones móviles y de escritorio según `verification.md`.
- Operaciones permitidas durante la auditoría: navegación, abrir/cerrar menús y hojas, selección OCR local, zoom/rotación del visor y validación de formulario vacío. No se completaron/cancelaron sesiones, aceptaron invitaciones, crearon objetos, subieron fotos al servidor ni ejecutaron borrados.
- Las capturas y resultados crudos se conservan temporalmente en `/tmp/listys-ui-audit-evidence/` y archivos de auditoría en `/tmp`; no se versionan. No exportar la sesión. Las fotos se enmascaran en las capturas de revisión.
- No hay comparación directa certificada con el canvas externo v2: su URL no fue accesible. Se leyó `docs/design/DESIGN.md`, incluidas sus excepciones y gaps. No se ejecutó la suite E2E bloqueada ni migraciones.

## Prioridad

P1: corregir antes de aceptar la preparación visual del flujo; P2: fricción relevante a resolver en esta pasada; P3: acabado. No se ha demostrado un P0 de bloqueo total de la app. Los bloqueos funcionales están en `functional-follow-up.md`.

Un tamaño inferior a 44 px se contrasta con el requisito táctil de Listys. No se etiqueta automáticamente como incumplimiento WCAG AA: WCAG 2.2 establece un mínimo diferente y excepciones que se deben evaluar por control.

## Patrones que se conservan

- Dashboard sin overflow horizontal en los cinco anchos inspeccionados; tabs móviles estables de 48 px y cuenta de 44 px.
- Las filas de compra y recibos ya amplían el checkbox mediante label/área envolvente: medir el glyph de 22 px aisladamente sería un falso positivo.
- Categorías usan botones nativos y estados expandibles; numerosas acciones destructivas ya tienen confirmación y consecuencias claras.
- Visor de fotos ocupa el viewport, dispone de botones de zoom/rotación/ajuste y alternativas a gestos; apertura con foco interno verificada. Zoom y rotación se ejercitaron sin modificar datos.
- Existen variantes compartidas, tokens, skeletons, test ids y varios fallos seguros. La propuesta extiende esa base en vez de duplicarla.
- Las capturas de entrada tomadas antes de finalizar una transición no se usan para afirmar que una hoja queda permanentemente fuera de pantalla. Se repitieron capturas estables para los casos analizados.

No se da una puntuación global de accesibilidad/performance: faltan lector de pantalla real, dispositivo táctil, Safari, teclado virtual, métricas de rendimiento y comparación directa con v2. Un número global sugeriría más cobertura de la obtenida.

## Referencias de criterios

- Nombres, foco, reflow, contraste, estados y semántica se contrastan con [WCAG 2.2](https://www.w3.org/TR/WCAG22/). El requisito de producto de 44 px es deliberadamente más amplio que el mínimo AA de target size.
- Se consultaron las [Web Interface Guidelines de Vercel](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) para revisar HTML, formularios, foco y feedback. Sus preferencias editoriales no sustituyen al sistema de diseño ni añaden nuevas funciones al alcance.
- Secuencia recomendada de acabado: `impeccable harden` para foco/estados, `adapt` para mobile, `clarify` para copy, `animate` para movimiento y `polish` al cerrar cada lote. Las tareas OpenSpec son la fuente ejecutable del plan.

El contexto de Impeccable también señaló `buildPath` sin definir en su configuración local. Es un ajuste de su flujo de dirección visual, sin efecto sobre esta auditoría; no se reparó configuración ajena como efecto secundario.
