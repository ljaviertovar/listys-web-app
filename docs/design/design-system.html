Assumptions (pending confirmation)

  • DS documentation is in English (the repo docs are English; the old HTML reference is Spanish).
  • Scope is the authenticated app plus the shared components. The landing page keeps its own documented exceptions (white page ground, 6px base radius, mock-up internals); they are not part of this DS.
  • Included beyond what the code has today: Tertiary button, Switch, Slider, Segmented control and tabs, One-time code, Delta. They come from the old reference or DESIGN.md and are “not implemented yet” in code, which is neutral.
  • Not included (specified in DESIGN.md, unused by the product today): data table. Add it with the update command when a screen needs it.
  • Field radius 16px, control radius 12px, card/dialog radius 24px, pill only for avatars, switches and progress.
  • Touch targets: 44×44px is the rule; compact controls (24/32/36px visual) must provide a 44px hit area or be one of the documented exceptions.
  • Fonts are not loaded by this page (offline file). Plus Jakarta Sans, Inter and IBM Plex Mono render if installed, else the fallback stacks.

Getting started

  1. Open this page; it is the only source of truth for UI. Toggle light/dark in the top bar.
  2. Start from the tokens: express the design through theme tokens in src/app/globals.css and variants in src/components/ui/. Do not invent colors, spacing, radii, type or variants.
  3. Find a core component, then a pattern, before writing markup. If none fits, derive from the closest pattern and say which.
  4. Configure components with their props and variants; className is for layout only (see the project’s styling rules).
  5. After UI work run the gate (/appds:gate <files>). To add components or screens to this DS run /appds:update; for a drift report run /appds:audit.

Accessibility guidelines

  • WCAG 2.2 AA floor: 4.5:1 for text, 3:1 for large text and essential UI boundaries. Cyan scan/primary never carries text; use scan/strong.
  • Meaning is never color alone: badges carry text, progress carries a value, selected rows carry a check and an accessible checked state.
  • Targets are 44×44px in shopping, upload and mobile navigation. A control may look smaller only when its row or padding supplies a 44px hit area.
  • Keyboard focus is a 2px action-blue ring with a 2px offset. Never remove it for a color change alone.
  • Dialogs trap focus, have an accessible title and restore focus. Drag-and-drop always has a file-picker equivalent; reordering has a keyboard or menu alternative.
  • Receipt images: descriptive alt text with page position (“Receipt page 2 of 3”). Decorative chrome and the scan seam are aria-hidden.
  • OCR and realtime status use one polite live region; a blocking error may announce assertively once.
  • Sticky bottom actions respect env(safe-area-inset-bottom); no core task needs horizontal scrolling at 320px. UI copy is localizable; amounts, dates and plurals use locale-aware formatters; layouts tolerate 30% text expansion.
